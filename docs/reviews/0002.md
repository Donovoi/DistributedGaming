# Work policy review

Date: 2026-11-24

Scope: small commits, prompt push and merge, and test location. No harness code changed. Goal progress stays at 20%.

## Round 1: design challenge

An independent reviewer checked the proposed policy before the edit.

| Finding | Change |
| --- | --- |
| A remote worker could still leave the coordinator on the user's PC. | Apply the rule to both roles. Include documentation checks, builds, installs, benchmarks, game runs, and capture. |
| A local VM could still make the host hard to use. | Prefer remote execution. Require CPU, memory, and I/O limits for a local VM. WSL alone is not enough. |
| Standing merge permission could be read as permission to skip checks. | Require both detractor rounds, current checks, and branch rules. Recheck when the head or base changes. |
| Small commits could omit their documentation. | Require the README and other needed documentation in each commit. Leave the score unchanged when no acceptance check closes. |
| Test records could expose private hosts or misstate earlier runs. | Record location, commit, and result with safe host labels. Keep earlier records accurate. |

## Round 2: final challenge

A second independent reviewer read the four-file documentation diff. No blocking findings remained. The reviewer checked small commits with documentation, merge checks, both harness roles, VM limits, unchanged progress, and accurate earlier records.

Both reviews used read-only file and Git inspection. No builds, tests, or desktop app actions ran during review.

## Validation

No local tests were run for this policy change. The PR uses the existing Linux and Windows checks on GitHub-hosted VMs. The PR must pass those checks for its final head before merge. The GitHub checks record the tested commit and results.

This policy adds no game capture, patch, replay, or performance result. No new milestone is complete.
